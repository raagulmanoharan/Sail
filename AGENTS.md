# Sail: Codex multi-agent instructions

This is a research-first startup project. The existence of these instructions is NOT evidence that agents have run.

## Gate 1: real parallel discovery
If your Codex environment supports spawning independent subagents, launch three agents with distinct isolated deliverables:
- Product strategy: `agents/product-strategy.md` -> `workstreams/product-strategy.md`
- Competition: `agents/competitive-research.md` -> `workstreams/competitive-research.md`
- GTM: `agents/gtm.md` -> `workstreams/gtm.md`

Use actual subagent tools. Record execution evidence and any blockers. Do not impersonate other agents or claim autonomy without it. Synthesize findings in `docs/decisions/product-definition.md`, including BUY/BUILD evidence, buying role, recurring value, distribution and host constraints, first paid pilot, product category, and kill criteria. STOP for founder approval. No UI mockups or landing-page coding before approval.

## Gate 2: design in parallel
After approval, launch independent UX, visual design and copywriting workstreams. UX must specify buyer journey and actual product experience. Visual design must create an original brand system. Copy must communicate the commercial proposition without overstating existing capabilities. Independent critic evaluates work before engineering.

## Gate 3: build and verify
Frontend implements approved direction, QA tests functionality, accessibility, mobile and claims separately. No fake logos, testimonials, transactions, security attestations, platform approvals, or unsupported integrations. Do not publish or collect leads without approved hosting/privacy/contact setup.

## Reporting
For every subagent: task, agent identity, tool confirmation, output path, evidence, unresolved questions. Clearly distinguish verified facts, assumptions and proposed features. Favor thoughtful product definition over flashy unsupported mockups.
